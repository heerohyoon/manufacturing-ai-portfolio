# 평가 계획서 (Pre-registration)

이 문서는 평가 데이터를 열기 전에 작성하고 커밋한다. 아래 규칙은 평가 데이터 결과를 본 뒤에 바꾸지 않는다.
바꿔야 할 일이 생기면 이 문서를 수정하는 대신 "변경 기록"에 이유와 함께 남긴다.

## 1. 데이터

- WM-811K 중 라벨 있는 웨이퍼 172,950개. 원본 분할(`trianTestLabel`)을 그대로 쓴다.
  - 학습 54,355개(5,809 로트), 평가 118,595개(4,953 로트), 겹치는 로트 없음
- 평가 데이터는 `scripts/final_evaluation.py`에서만 연다. `tests/test_data.py`가 다른 곳의 호출과 파일 직접 읽기를 막는다.
- 클래스 9개: Center, Donut, Edge-Loc, Edge-Ring, Loc, Near-full, Random, Scratch, none

## 2. 전처리

- 모든 맵을 **64×64**로 맞춘다. 각 축에서 출력 칸 하나에 대응하는 원래 칸들 중 가장 큰 값을 쓴다(0 < 1 < 2).
  - 64칸 이하인 축은 칸을 그대로 늘리는 것과 같다.
  - 64칸보다 큰 축은 합쳐지는 칸 중 불량(2)이 하나라도 있으면 불량이 된다. 가는 선(Scratch)을 보존하기 위해서다(EDA 6절).
- 64×64 맵에서 두 장의 0/1 지도를 만든다: 칩 위치(값 > 0), 불량 칩 위치(값 = 2).

## 3. 비교할 모델

| 이름 | 입력 | 모델 | 목적 |
|---|---|---|---|
| M0 크기 기준선 | 원래 맵의 세로, 가로, 칩 개수 | LightGBM | 맵 내용을 보지 않고 제품(크기)만으로 얼마나 맞히나 |
| M1 특징 모델 | 64×64 맵에서 계산한 모양 특징 (크기 정보 제외) | LightGBM | 사람이 설계한 특징으로 얼마나 맞히나 |
| M2 CNN | 64×64 맵 두 장 (칩 위치, 불량 위치) | 작은 CNN | 모양을 직접 학습하면 얼마나 더 맞히나 |

### M0
- `n_estimators=200`, `class_weight="balanced"`, `random_state=0`. 튜닝하지 않는다.

### M1 특징 (64×64 맵 기준, 칩이 있는 칸만 분모로)
- 전체 불량 칩 비율
- 중심 거리로 나눈 고리 5개(0~0.2, ~0.4, ~0.6, ~0.8, 0.8~)의 불량 비율
- 바깥쪽(중심 거리 0.6 이상)을 방향으로 나눈 부채꼴 8개의 불량 비율, 그 표준편차와 최댓값-최솟값 (한쪽에 몰렸는지)
- 가장 큰 불량 덩어리(상하좌우로 이어진 불량 칸): 전체 불량 중 비율, 중심까지 거리, 길쭉한 정도(주축 길이 비)
- 불량 덩어리 개수(칩 수로 나눔)
- 원래 맵의 크기와 칩 개수는 **넣지 않는다**. 모양만으로 얼마나 맞히는지 보기 위해서다.
- LightGBM: `n_estimators=500`, `learning_rate=0.05`, `class_weight="balanced"`, `random_state=0`.
  후보 `num_leaves ∈ {15, 31}`, `min_child_samples ∈ {20, 50}`. 4절 교차검증 매크로 F1 평균이 가장 높은 설정을 쓴다.

### M2 CNN (PyTorch)
- 구조: [합성곱 3×3 → 배치 정규화 → ReLU] × 2 → 최대 풀링, 이 블록을 채널 32, 64, 128로 세 번 → 전역 평균 풀링 → 드롭아웃 0.3 → 출력 9개
- 손실: 교차 엔트로피. 클래스 가중치 = (전체 수 / (9 × 클래스 수))의 제곱근 (드문 클래스를 키우되 너무 극단적이지 않게)
- 데이터 늘리기(학습 때만): 90도 회전 0~3회, 좌우 뒤집기 50%. 패턴 이름은 방향과 무관하므로.
- AdamW, 학습률 1e-3, weight decay 1e-4, 배치 256, 최대 30 에폭, seed 0
- 4절의 검증 fold에서 매크로 F1이 5 에폭 연속 오르지 않으면 멈추고, 가장 좋았던 에폭 수를 기록한다.
  최종 모델은 학습 데이터 전체로 그 에폭 수만큼 다시 학습한다.
- 구조와 학습 설정은 튜닝하지 않는다.

## 4. 교차검증 (학습 데이터 안)

- `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)`, 그룹 = 로트
- M1 설정 선택: 5개 fold 평균 매크로 F1
- M2 멈출 시점: fold 0 하나를 검증으로 쓴다 (학습 시간 때문)
- 세 모델의 교차검증 매크로 F1을 모두 기록한다. 이 값은 참고용이고, 평가 결과를 보고 모델을 고르지 않는다.

## 5. 판정

- 9개 클래스 중 예측 확률이 가장 높은 클래스로 판정한다. 클래스별 기준값을 따로 조정하지 않는다.

## 6. 보고할 지표

| 구분 | 지표 |
|---|---|
| 주 지표 | 매크로 F1 (9개 클래스 F1의 단순 평균) |
| 함께 보고 | 클래스별 정밀도, 재현율, F1. 정답 기준으로 정규화한 혼동행렬 |
| 참고 | 정확도 |

같은 지표를 아래 부분집합에서도 보고한다.

- **새 크기**: 원래 맵 크기(세로×가로)가 학습 데이터에 한 번도 없었던 평가 웨이퍼. 크기 지름길이 통하지 않는 상황이다.
- **중복 제외**: 학습 데이터와 칸 값까지 똑같은 맵을 뺀 평가 웨이퍼.
- 부분집합에 없는 클래스는 그 부분집합의 매크로 F1에서 빼고, 몇 개 클래스로 계산했는지 함께 적는다.

## 7. 불확실성

- 같은 로트 웨이퍼끼리 비슷하므로 **로트 단위**로 복원추출한다. 평가 로트를 1000번 다시 뽑아(seed 0) 95% 백분위 구간을 구한다.
- 대상: 각 모델의 매크로 F1, 두 모델 간 매크로 F1 차이(M1 - M0, M2 - M0, M2 - M1). 차이는 같은 표본으로 계산한다.
- 해석: 차이 구간이 0보다 위에 있을 때만 "낫다"고 쓴다. 0을 포함하면 "우열을 단정할 수 없다"고 쓴다.

## 8. 최종 평가 이후에 하는 분석 (결과로 결정을 바꾸지 않음)

- Grad-CAM: M2가 맵의 어느 부분을 보고 판단했는지 클래스별 예시로 확인
- 오분류 사례: 많이 헷갈린 클래스 쌍의 맵을 직접 보고, 라벨 오류로 보이는 경우를 기록
- 같은 분할을 쓴 기존 연구와의 비교는 전처리와 지표가 달라 참고로만 적는다.

## 9. 사전 지식 공개

- 평가 데이터에 대해 아는 것: 웨이퍼 수와 로트 수, 학습과 겹치는 로트가 없다는 것, 학습 데이터와 똑같은 맵이 3,158개라는 것. 평가 데이터의 라벨 분포는 보지 않았다.
- 이 데이터셋은 공개된 지 오래되어 기존 연구 결과가 많이 알려져 있다. 모델 구조와 설정은 그 결과에 맞추지 않고 위에 적은 대로 미리 정했다.
